## 1. 命名：为什么用 `Ct` 前缀（决策记录）

### 决策：所有自定义类以 `Ct` 开头（Crisp Type）

**备选方案对比**

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| `Ct` 前缀（Crisp） | 项目辨识度高；与 Qt（`Q`）、STL 无冲突；全局唯一前缀利于搜索/自动补全 | 稍冗长 | ✅ **采用** |
| 仅 `C` 前缀 | 短 | 与微软 MFC `C*`、无数第三方 `C*` 类冲突；无法标识项目 | ❌ 不采用 |

**理由**
1. `C` 前缀在 Windows 生态里被 MFC/ATL 大量占用，搜代码极易误命中。
2. `Ct` 明确标识"这是本项目的类型"，与第三方、标准库一眼区分。
3. 类内嵌套类型/辅助 struct 可不带前缀（它们已处于 `CtXxx` 的命名空间内），避免视觉噪音。

**示例**
```cpp
namespace crisp {
class CtEvent;          // 事件基类
class CtDispatcher;     // 分发器
class CtEventLoop;      // 事件循环
class CtTimerSource;    // 定时器源
}
```
> 注意：模板参数、局部变量、函数参数不要求前缀；仅**类型名**要求。

## 2. 文件组织：.cpp / .h 严格分离（你的要求分析）

### 你的要求
1. 严格区分 `.cpp` 和 `.h`，不混写。
2. 函数遵守单一职责。
3. 函数行数有限制。
4. 重要函数生成注释（英文注释）。
5. 文件编码注意可移植性。

### 合理性分析：**全部合理，且都是工程最佳实践**

| 要求 | 合理性 | 补充说明 |
|------|--------|---------|
| .cpp/.h 分离 | ✅ 合理 | 减少编译依赖、加速增量编译、隐藏实现细节（Pimpl 友好）、避免 ODR 违规。**例外**：模板、`constexpr` 函数、`inline` 必须放头文件——这是 C++ 语言规则，不是"混写"。 |
| 单一职责 | ✅ 合理 | 可测试性、可读性、可维护性的基石。 |
| 行数限制 | ✅ 合理，但要弹性 | 建议 60 行为硬上限、40 行为软目标。**机械限制不如"职责单一"重要**：一个 40 行的 switch 分发器可能比 3 个 15 行但耦合的函数更好。 |
| 重要函数注释 | ✅ 合理 | 建议"接口注释 + 复杂实现内联注释"，Doxygen 风格，**英文**（团队国际化 + 工具链编码安全）。 |
| 文件编码可移植 | ✅ 合理 | UTF-8 无 BOM + LF 行尾 + 避免源码内嵌非 ASCII，是跨编译器（MSVC/GCC/Clang）安全的基础。 |

### 落地规则（写入 AGENTS.md）
- 头文件：声明 + `inline`/模板实现。
- 源文件：所有非模板实现。
- 函数体 ≤ 60 行（硬性）；> 60 行必须拆分并说明理由。
- 公开 API 必须 Doxygen 注释；复杂私有函数至少一行说明意图。

## 3. 借鉴 muduo 的编码方式

> [muduo](https://github.com/chenshuo/muduo)（陈硕）是 C++ 网络库标杆，其风格与现代 C++ 高度契合。

### 可借鉴（与本项目原则不冲突）✅

| muduo 风格 | 说明 | 本项目落地 |
|-----------|------|-----------|
| RAII 管理资源 | 锁、定时器、连接全部 RAII | 强制：`CtScopedLock` 等 |
| 非阻塞 + 事件驱动 | 单线程事件循环模型 | 事件循环设计已采用 |
| 小而专的类 | 每个类职责单一 | 强制 SRP |
| 明确线程模型 | 每个类注明"线程安全/非线程安全" | 注释规范中强制 |
| 性能敏感用对象池 | 减少分配 | 事件对象池 |
| `using` 类型别名清晰化 | 如 `using TimerCallback = std::function<void()>` | 模板事件类型 |
| 头文件自包含 | 每个头文件可独立编译 | 规范强制 |
| 无全局可变状态 | 避免隐式依赖 | 架构强制 |

### 不借鉴（与本项目原则相悖）❌

| muduo 风格 | 原因 |
|-----------|------|
| 大括号风格/缩进细节照搬 | 风格主观，采用本项目统一风格 |
| 某些 C 风格写法（部分历史代码 `snprintf` 等） | 本项目倾向现代 C++（`std::format` 待工具链支持后启用） |
| 类名全小写下划线（如 `EventLoop` 无前缀） | 与 `Ct` 前缀决策冲突 |

## 4. 现代 C++ 优先 + 嵌入 Qt 的编译风险分析（你的问题 4）

### 结论：**没有不可逾越的编译风险，但有一个已知工具链约束**

| 风险点 | 分析 | 对策 |
|--------|------|------|
| Qt 6.2.4 用 MinGW 8.1 构建 | 已成功编译并验证（本机 `D:\Qt\6.2.4`） | ✅ 无风险 |
| Qt 头文件与 C++17 冲突 | Qt 6 官方支持 C++17；Qt 6.2 要求 C++17 | ✅ 无风险 |
| **MinGW 8.1 的 `<filesystem>` bug** | GCC 8 libstdc++ 的 `fs_path.h` 缺 `operator!=`，`#include <filesystem>` 即编译失败 | ⚠️ **规避**：本项目暂不直接用 `std::filesystem`；用 Qt 路径 API（`QDir`/`QFileInfo`）或自研 `CtPath` 封装；后续升级 GCC ≥ 9 再启用 |
| 混合 Qt（qmake 产物）与 CMake 工程 | 只要通过 CMake `find_package(Qt6)` 使用安装好的 Qt，无冲突 | ✅ CMake 是标准做法 |
| moc 生成的代码与手写 C++ 共存 | moc 只是预处理器，产物是普通 .cpp，可被 CMake `AUTOMOC` 管理 | ✅ 无风险 |
| C++20 特性在 MinGW 8.1 | `__cplusplus` 只到 201709L，concepts/ranges/协程不可用 | ⚠️ **锁定 C++17**，C++20 特性留待工具链升级 |
| ABI 兼容 | 同一 MinGW 8.1 编译 Qt 和本项目，ABI 一致 | ✅ 无风险 |

### 结论
- **可以放心用现代 C++（C++17）嵌入 Qt**，编译风险可控。
- 唯一硬约束：**避开 `std::filesystem`**（GCC 8 工具链 bug），用封装层。
- 建议：本项目的自研核心（`crisp::event` 等）**不依赖 Qt**，只在需要替代/桥接 Qt 模块时才 `#include <Qt...>`，保证自研层可独立编译测试（这正是"逐步替代"的前提）。

## 5. 现代 C++ 特性使用清单（你的问题 5）

> 按本项目适用度排序。详细讲解见 `.github/skills/cpp-modern-best-practices/SKILL.md`。

| 特性 | C++ 版本 | 本项目用途 | 优先级 |
|------|---------|-----------|--------|
| `std::variant` + `std::visit` | 17 | 事件类型化分发（替代 switch+cast） | 🔴 核心 |
| `std::optional` | 17 | 可空返回值（替代哨兵值） | 🔴 核心 |
| `std::string_view` | 17 | 事件名、参数只读视图（零拷贝） | 🔴 核心 |
| `std::chrono` | 11+ | 定时器、超时（替代 int 毫秒） | 🔴 核心 |
| 智能指针 `unique_ptr`/`shared_ptr`/`weak_ptr` | 11 | 所有权表达、接收者生命周期 | 🔴 核心 |
| RAII（`std::scoped_lock` 等） | 17 | 锁、资源管理 | 🔴 核心 |
| `std::function` + lambda | 11 | 回调、事件处理器 | 🟠 高频 |
| `std::any` | 17 | 类型擦除的兜底（慎用） | 🟠 可选 |
| `if constexpr` | 17 | 编译期分支（`EventTraits` 特化） | 🟠 可选 |
| 结构化绑定 | 17 | 解构 `std::pair`/`variant` | 🟠 常用 |
| 折叠表达式 | 17 | 变参工具（如多事件注册） | 🟡 锦上添花 |
| `std::span` | 20 | 连续内存视图 | ⚠️ 等 GCC 升级 |
| 协程 `co_await` | 20 | 异步处理器 | ⚠️ 等 GCC 升级 |
| concepts / ranges | 20 | 约束模板 | ⚠️ 等 GCC 升级 |
| `std::format` | 20 | 格式化字符串 | ⚠️ 等 GCC 升级（或先用手写/`snprintf` 封装） |

## 6. 检查清单（供 code review / agent 自检）

- [ ] 类名以 `Ct` 开头？命名空间是 `crisp`？
- [ ] 非模板实现都在 `.cpp`？头文件只留声明 + inline/模板？
- [ ] 函数 ≤ 60 行？单一职责？
- [ ] 公开 API 有英文 Doxygen 注释？
- [ ] 源码 UTF-8 无 BOM、LF 行尾、无内嵌非 ASCII 字面量？
- [ ] 无裸 `new`/`delete`、无 C 风格 cast？
- [ ] 没用 `std::filesystem`（工具链 bug）？
- [ ] 线程语义有注释（线程安全/非线程安全）？
- [ ] 构建：CMake + MinGW，并行度 ≤ 2（防 OOM）？
